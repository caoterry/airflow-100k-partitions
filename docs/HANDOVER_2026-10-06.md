## State of the design: v2 **variant D** (code in `v2/`, environment `v2/ctl.sh`)

- One Spark job per batcher run; batcher `max_active_runs = K` = pool `v2_spark` size, so K runs overlap and the engine slots
  stay busy. When all K are busy, bells coalesce in `asset_dag_run_queue` and the next free run takes them all.
- Correctness of overlapping runs comes from idempotent, version-ordered output writes by the calc (`(account, dataset_version)`,
  readers use a latest-version view partitioned by business date, clustered by account, optionally compacted). This is a
  contract on the calc, not something Airflow guarantees.
- Journal = Airflow's `asset_state_store`: `done` and `failed` dicts written ONLY by the serial `v2_ledger` Dag (fed by the
  batcher's `v2_batches_finished` event); one `batch/<run>#<i>` key per job written by its own run. Two version spaces per
  account: `[dataset_version, marker]` (marker = row fingerprint or the dataset version for delta feeds).
- Failure: Airflow retries; then only that batch is marked failed; engine-named culprits stay failed, healthy accounts of the
  batch ring the bell once more (`ring_retry`); a failed account rides alone in a quarantine job and is retried automatically
  when a newer version lands; `check` turns the run red after the bookkeeping is done.
- Idle-time accumulation: `v2_debounce` (interim for a native debounce window, an upstream proposal): first bell starts a
  deferred hold (`DEBOUNCE_S`, needs the triggerer), then `forward` reads the whole window from the bell asset's event log
  (cutoff key written only by this Dag, 5 s margin) and emits ONE debounced bell; empty ticks start the next window and sweep
  bells stamped after a queue row (Airflow attaches to a run only events stamped before its queue row).
- Measured today: 10k accounts on variant C: whole run 171 s; 100k on C: whole run 182 s (lineage registration 120 s, `done`
  dict 2.1 MB); D: three bells 6 s apart ran as three overlapping runs, a fourth bell waited for the first run to end; debounce:
  three landings in one window became one job. 100k on D with debounce (version 2) was started at the end of the session:
  `v2/recordings/scale100k_D2.log` (gitignored) holds the result.
