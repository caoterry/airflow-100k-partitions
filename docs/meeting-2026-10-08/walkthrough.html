Two grains, one bucket: a table-by-table walkthrough

Four chapters, each a real recording (one snapshot every half second, Airflow 3.3.2 in a local environment, K=3, debounce window 10 seconds). Vocabulary: a partition is the key of a computation (in PnL it is the account); a computation has several input datasets, each with its own version. dag_run.run_type · who created this run

manualTriggered by hand with airflow dags trigger (CLI or REST): every producer landing in the kata is manual
asset_triggeredCreated by the scheduler because of an asset event: the debounce, batcher, ledger and downstream runs are all this kind. Which events it consumed is in dagrun_asset_event
scheduled / backfillCreated on a timetable or by backfill. Not present in our design: no cron, no watermark

state · the state of a dag_run or task_instance

queuedThe run exists but no task is running yet; or the task has been handed to the executor but no process has started
runningRunning
deferredThe task has handed its wait to the triggerer and the worker is released (debounce's hold and ledger's settle do this)
success / failedFinished normally / failed after exhausting retries. A failed dag_run only ever comes from the check task raising on purpose: the run is marked red, the bookkeeping is already done
up_for_retryThis attempt failed; Airflow will try again after retry_delay (spark retries=1, claim and publish 2)
upstream_failedNot run because an upstream failed: when spark fails, its publish ends in this state
skippedThe task raised AirflowSkipException itself: nothing to do, and it emits no asset event. Every task that "may be empty" ends the chain this way
(empty)The task_instance has not been scheduled yet; state is NULL

task_instance columns

run_idThe run's name; shown on this page as run <dag_run.id>. batch_id = run_id#index, so a batch key is shown as run <id> #0
map_index-1 = an ordinary task; 0,1,2… = which instance of a mapped task (run_batch is a mapped task group; variant D normally has only #0, with an extra #1 when a failure is isolated)
try_numberWhich attempt this is, starting at 1; becomes 2 after up_for_retry
poolThe slot pool the task occupies. spark is in v2_spark (K=3 slots = engine capacity); everything else is in default_pool

task_id · what each task does and which table it writes

landproducer (Dag v2_land): emits 1 event on the bell, extra = {dataset, version, partitions: {partition: marker}}. Does not write the journal
plandebounce (Dag v2_debounce, max_active_runs=1): takes the newest debounced event's window_end as the cutoff, finds the first bell with partitions after it (a few rows read) and hands "its timestamp + DEBOUNCE_S" to hold. If nothing is pending, skipped, and this run ends here
holddebounce: a DateTimeSensorAsync whose target time comes from plan's xcom (the window's first unforwarded bell + 10 s, D25); deferred until then, the trigger table gains one row; if the time has already passed it returns at once
forwarddebounce: reads from the bell's event log every bell in (cutoff, now − 5 s margin], merges them by partition and dataset, writes 1 window key and emits 1 debounced event pointing at it. If the window is empty, skipped. It rings no tick itself; that is sweep's job
sweep (debounce)debounce: trigger_rule=all_done. Only when bells stamped before this run started are still left after the cutoff (held outside the window by the margin, with no queue row of their own to start a run) does it ring one empty event on the private asset v2_debounce_tick to force the next run (D24). Normally skipped
claimbatcher (Dag v2_batcher): follows the pointer to GET the window key, reads done and failed once each, decides which partitions are due (any dataset with a newer version and a changed marker), writes the batch/… key (state=claimed), and puts the batch list in xcom. If nothing is due it returns empty and does not read done
run_batch.sparkbatcher: stand-in for the engine (sleep 6 seconds + 0.5 seconds per partition), holds one v2_spark slot, sets the batch key to running; on the final failed retry sets it to failed and writes culprits
run_batch.publishbatcher: sets the batch key to done and emits 1 event on v2_pnl pointing at the batch key
finalizebatcher: trigger_rule=all_done, reads this run's batch keys for a summary; emits FINISHED (for the ledger). If claim found nothing, skipped
tickbatcher: if this run had work, rings one empty event on the private asset v2_batcher_tick: Airflow attaches to a run only the events stamped ≤ the queue row's created_at, so a debounced event that arrived while the run was busy must be picked up by the next run (the attachment rule); with K runs in parallel the batcher has no shared cutoff and cannot read the log the way forward does, so it ticks. No work, skipped
ring_retrybatcher: rings debounced once more for the healthy partitions of a failed batch, those not named by the engine (and, once only, the partitions of a job that never reached publish). If there are none, skipped
checkbatcher: raises if any partition went into failed, turning the run red. Color only; the bookkeeping was completed before it
settleledger (Dag v2_ledger, max_active_runs=1): a TimeDeltaSensor(deferrable=True), deferred until run_after + LEDGER_MARGIN_S (5 s): K finalizes commit concurrently, so timestamp order is not commit order; waiting out the margin lets one fold take everything in one pass
foldledger: the sole writer of done and failed. Reads ledger/cutoff, reads the FINISHED event log in (cutoff, now − 5 s] and folds the batch keys: done takes the highest version per (partition, dataset), failed gets the culprits; then writes cutoff; finally reports whether any event was left inside the margin
sweep (ledger)ledger: trigger_rule=all_done. Only when FINISHED events stamped before this run started were left inside the margin does it ring one empty event on the private asset v2_ledger_tick (D24). Normally skipped
reviewdownstream example (Dag v2_exceptions): reads the PnL events from triggering_asset_events, follows the pointer to GET the batch key, folds by partition and dataset (max version), result goes to xcom
sweepdownstream example: if it did work, rings one empty event on the private asset v2_exceptions_tick (the attachment rule/5): like claim it uses triggering events, so every run that did work is followed by one sweep-up run. No work, skipped
ringoperator (Dag v2_requeue): rings debounced again for the partitions in failed, at their original versions. Not used in the kata

asset · what each of the eight assets is

v2_inputs_landedbell: every input dataset's producer rings it. extra = {dataset, version, partitions: {partition: marker}}. debounce subscribes to it
v2_inputs_debounceddebounced bell: forward rings it once per window, extra = {window: key, window_end, n_partitions, bells}; the partition list lives in the key. batcher subscribes to it; ring_retry and requeue ring it too (small payload)
v2_debounce_tickdebounce's private tick: sweep rings it only when bells were left inside the margin with no queue row to start a run for them (D24). debounce's schedule is bell | this tick. Normally silent
v2_batcher_tickThe batcher's private tick: an empty event whose only purpose is to start the next run to sweep up. Only batcher subscribes
v2_pnlbatch complete: publish rings it once per job, extra = {batch: key, n_partitions, datasets}. Downstream Dags subscribe to it (the R4 chain). Its state store holds the journal
v2_batches_finishedletter to the ledger: emitted by finalize, extra is the batch_ids. Only ledger subscribes
v2_ledger_tickThe ledger's private tick: sweep rings it only when FINISHED events were left inside the margin (D24). The ledger's schedule is FINISHED | this tick. Normally silent
v2_exceptions_tickThe downstream example's private tick. Consumers sharing one asset each ring their own, so none wakes another

asset_state_store keys · our journal (all on v2_pnl)

window/&lt;window_end&gt;One per window: {partitions: {partition: {dataset: [version, marker]}}, bells, window_end}. Only forward writes it. The debounced event points at it
batch/&lt;run&gt;#&lt;i&gt;One per job: {state, versions: {partition: {dataset: [version, marker]}}, retry, culprits, error}. state is advanced by claim→spark→publish in turn; only its own run writes it
done{partition: {dataset: [version, marker]}}, what has been computed. Only fold writes it
failedSame shape: partitions the engine named as failed, waiting for a new version. Only fold writes it
ledger/cutoffTimestamp of the last FINISHED event fold has folded (only events older than the 5 s margin are folded); fold writes done/failed first and this last, so folding again is idempotent

Other tables

asset_dag_run_queueThe row that queues when an event has arrived but the target Dag cannot start a run yet (it is at max_active_runs). Primary key (asset, dag): however many events arrive there is only this one row, and created_at stays at the first. Deleted once the run is created
dagrun_asset_eventThe run ↔ event link table. triggering_asset_events inside a task is a lookup of this
triggerThe wait record of a deferred task, polled by the triggerer process. hold sits here while it waits for the window close, settle while it waits out the ledger margin; deleted when the time is up
xcomSmall values passed between tasks. claim's return_value is the batch list; what spark passes to publish is here too
variableAirflow Variable. v2_poison is the test poison: the engine fails on these partitions. The value is stored encrypted, which is why it displays as garbage
